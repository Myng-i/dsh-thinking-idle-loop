# 现象：一串「做。」，一轮白干

## 1. 账本里的实录

守卫插件在判定「思考空转」时会中止本轮生成，并把最后 24 行思考写进账本 `<DSH_HOME>/attention-health/guard-trips.jsonl`。典型的一条 `tail` 长这样（内容按原样保留，仅截断）：

```
先测连通性。
做。
`curl -sv …` 看详细。
或者 `curl -sI <某个域名>`。
做。
做。
可能 DNS 或代理问题。
测。
做。
做。
执行。
做。
（执行）
做。
（做）
做。
好。
做。
```

机制：**「决定要做」和「真的做」之间反复自我授权**。thinking 流里没有执行通道，唯一的出口是输出 tool call 或者结束 turn；两者都没发生时，模型只能在原地自回归复读。

## 2. 触发场景高度一致

23 条记录里，尾部几乎都出现在「受阻点之后」：

- 网络请求连不上（`exit code 7` / `CURLE_COULDNT_CONNECT`）
- 等交互式 CLI 的隐藏输入（`login` 提示）
- 等子代理返回（「两个都在跑，等通知」）

**受阻点 + 长上下文** 是共同土壤。这解释了为什么它常在「看起来很简单」的任务里爆：任务简单，但某一步卡住了。

## 3. 账本统计（截至 2026-10-24）

| 项 | 值 |
|---|---|
| 总记录 | 23 |
| `short-line-repeat`（同一短行高频） | 15 |
| `spinning`（窗口内内容种类过少） | 8 |
| 涉及会话 | 9 |
| 时间跨度 | 2026-10-11 → 2026-10-24 |

填充词还在「进化」：空代码块 → `好` / `嗯` → `走` → `Go.` → `做。`。这提示它是**形式坍缩**（模型找不到下一步的形式表达），而不是对某个词的语义执念。

## 4. 样本会话规模

| 指标 | 值 |
|---|---|
| 原始日志（压缩） | 2 966 152 B |
| 解压后 | 6 896 781 B |
| 事件数 | 3 669 |
| turn / step / tool call | 21 / 421 / 435 |
| 单轮最长 step（T4） | 102 |
| 被守卫中止的 turn | 5 轮（T6 / T8 / T11 / T19 / T21） |

421 个思考块（每个 step 一块）里：

- 第一个 `做。` 出现在第 5 块（属 T1，该块 152 行，仅 1 次）——当时还是正常用词。
- 从 T5 起，单块 `做。` 的中位数 11 次，最多 105 次（块 [418]，T21）。
- 全会话 `做。` 共出现 **3 531 次**，集中在后半段。
- 密度峰值不是某一轮的开头，而是块 [382]（T17，162 字符里有 32 行是碎片，197.5‰）；块 [226]（T6，541 字符、25 次 `做。`）是更早的一个典型坍缩点，开头还是正常推理（对 `exit code 7` 的判断），几行之后就坍缩成上面的实录。

## 5. 一个容易误判的地方

中止 `cancel()` 并不解决它：模型不知道自己为什么被中止，下一轮带着同样的上下文重开，于是出现「第 6 / 8 / 11 / 19 / 21 轮连环中止，而密度还在涨（13.8‰ → 42.6‰ → 117.6‰）」的现象。这也是后面改「先引导、用尽才中止」的直接动因。
